工具使用、多个角色和图像输入描述的是系统怎样工作；强化学习描述的是怎样由奖励更新策略。把这两个维度分开，就能理解为什么外观相似的 Agent 论文，训练方法可能完全不同。

本篇补齐课题库中的相关路线；核心信用与验证器概念分别见 [P3](/2026/11/23/llm-rl-p3-credit-assignment/)、[P4](/2026/11/23/llm-rl-p4-verifier/)。

## 1. ReAct：先理解交互协议

ReAct 把推理文本与环境动作交替组织：模型读观察，形成下一步意图，调用搜索或其他工具，再读返回内容。

```text
问题 → 模型决定搜索 → 搜索返回证据
     → 模型继续推理 → 再查或给出答案
```

这个协议既可以由冻结 Qwen 按提示执行，也可以放进训练系统。仅观察到工具调用链，无法判断有没有参数更新。Toolformer 则用筛选后的工具调用数据改进语言模型，其学习信号与终局奖励驱动的策略优化不同。

## 2. Search-R1：把检索交互纳入奖励学习

Search-R1 让语言模型在求解中调用检索，把结果放回上下文，再按任务结果更新策略。工具返回的原文是环境观察；模型生成的查询、推理和答案才是动作。

因此训练掩码特别重要。假设检索器返回 500 个 token，它们可以作为下一次前向的上下文，却不应全部被当作 Qwen 刚才主动生成的动作去奖励。

评价时需要同时记录答案正确率、查询次数、检索成本和输入长度。只看到答案变好，无法区分更好的查询策略与更多的搜索预算。

库中的多智能体 RAG、深度搜索和层次任务分解沿着这条线扩展：不同角色负责拆题、检索或综合，但仍要逐一检查奖励究竟更新了哪个角色。

## 3. SayCan：语言相关性与技能可行性

SayCan 把高层语言规划与已学技能的价值联系起来。语言模型判断“这个技能是否有助于当前目标”，技能价值判断“在当前状态下能否执行成功”。

教学上可写成：

$$
\text{score}(\text{skill})
\propto P_{\text{language}}(\text{skill}\mid\text{instruction, history})
\times P_{\text{success}}(\text{skill}\mid s).
$$

如果“拿海绵”与清理洒水很相关，但机器人够不到海绵，可行性低；另一个稍绕远却能完成的技能可能得到更高综合分。

在此结构里，RL 可以用于学习底层技能与价值；大语言模型提供高层知识。用 Qwen 与已经学过的小 Actor-Critic 来理解角色关系很合适，但不能据此把原论文改称 Qwen/MAPPO 实现。

## 4. Eureka 与 ReMAC：语言模型写奖励，小策略训练

Eureka 使用语言模型生成奖励代码，依据策略训练反馈改进奖励设计。ReMAC 将奖励设计扩展到团队与成员层次，并提供协作操作任务。

一次迭代可以包含很多下层策略训练，故 LLM 调用数少，不一定意味着总体计算便宜。实验要分别计入奖励候选数、每个候选的训练种子与环境步数。

生成程序还需要检查是否能执行、是否偷读隐藏真值、奖励范围是否合理。实践 E3 会展示本地 90 个奖励程序的解析与截断问题如何改变模型比较。

## 5. 多模态与 VLA 改变了什么

视觉语言动作模型（VLA）可以把图像、语言指令和动作放进同一策略。多模态也可以只用于观测编码：视觉模型看懂场景，小控制器再决策。

| 系统 | 需要先确认的更新对象 |
|---|---|
| 冻结视觉模型＋小 Actor | 通常是控制器与价值网络 |
| VLM 给偏好或奖励 | 下层策略，可能另有评分模型 |
| VLA 接受策略微调 | 动作生成相关的模型参数或适配器 |
| 多机器人语言协商 | 逐角色检查是否训练，是否只改变提示与规划 |

引入图像以后，还应检查相机视角、遮挡、历史帧、动作频率和视觉编码是否共享。若所有角色都能看到全局图像，原本要研究的私有信息缺口可能已经消失。

课题库的 cooperative VLA、语言协商机器人与 VLM 奖励研究因此分别归入不同训练路线；“多模态”作为交叉标签保留。

其中 *Cooperative Multi-Agent VLA Models via Reinforced Fine Tuning* 的归档版本采用三阶段：先按初始状态收集数据，持续失败的配置补充人工示范；再按个体正优势筛选轨迹做离线微调；最后冻结 VLA，通过在线 RL 调节潜在噪声空间中的控制策略。同一篇论文在不同阶段，也会切换被更新的对象。

该版本封面标注 ICLR 2027 在审。它为多机器人低层协调提供了具体训练路线，与仅让冻结语言模型协商任务分工的系统分开阅读。

## 6. 自博弈、TTRL 与推理时采样

自博弈可以由出题者和解题者交替学习，奖励与数据筛选共同影响训练。Absolute Zero 属于阅读这一方向的入口。若题目越来越容易获得代理奖励，却离目标任务越来越远，系统也可能在自己的闭环里失去有效监督。

测试时强化学习（TTRL）在测试阶段利用可获得的反馈更新参数。若用多数答案当奖励，多数本身错误就可能推动错误收敛；它需要讨论奖励来源、测试任务隔离和少数正确答案的保留。

Best-of-N、自一致投票和树搜索则可以只增加推理采样，不更新参数。同一个冻结 Qwen 多回答几次就变得更准，属于推理预算改变。实践 E4 的路由与搜索多数是这类冻结模型实验。

## 7. SFT、DPO 与 RL 的关系

SFT 用目标文本训练模型模仿；DPO 使用成对偏好数据构造直接优化目标；在线策略 RL 采样交互并利用奖励更新策略。三者可以进入同一条后训练管线，数据来源与优化目标各有职责。

DeepSeek-R1-Zero 用于研究奖励驱动推理；DeepSeek-R1 的完整管线还包含冷启动、监督数据与多阶段训练。引用时需要指明讨论的是哪个阶段。

Agent Lightning 等框架进一步处理执行系统与训练器的接口。框架能连接轨迹，不代表每个接入应用已经完成有效强化学习；具体任务仍要检查输出概率、奖励和更新对象。

## 8. 与当前课题怎样连接

当前优先比较的是验证器错误、压缩记忆和信用覆盖。检索、机器人、多模态、自博弈提供任务与方法背景，具体主攻尚待选择。
