## 模型变大后，瓶颈在哪里

给模型多喂一倍输入，内存和等待时间会各增加多少？先找出随输入增长的量：权重可以原封不动，注意力要处理更多位置之间的关系，解码还要保存更多历史键值。换成多个专家之后，又会多出把 token 分派给专家的开销。课堂后半段把同样的系统思路用到了芯片设计：生成候选只是第一步，还要检查功能和时序。

## 算法、数据、算力怎样配合

| 要素 | 课堂主线 | 系统层面的追问 |
| --- | --- | --- |
| 算法 | 反向传播、优化器、连接方式与训练目标 | 算子计算量、并行方式和数值稳定性是什么？ |
| 数据 | 自监督预训练，再针对场景适配 | 数据质量、分布、吞吐与任务评价怎样控制？ |
| 算力 | CPU、GPU、TPU 与专用处理器 | 算力、容量、带宽、通信和功耗是否匹配？ |

预训练从大规模数据中学习可迁移表示，微调则针对特定任务调整模型。校园场景识别是一个直观例子：通用模型迁移到特定校园后，需要适应当地的场景分布，再用独立划分的数据评价效果。自监督学习的训练目标则从数据本身构造，例如预测序列中的下一个 token。

单个神经元做加权、聚合和非线性变换，网络通过连接结构组织这些运算。加深、加宽会改变容量，但语言能力还取决于表示、注意力、数据与目标。人工参数与生物突触不是同一种对象，全脑与皮层神经元数也不是同一口径，不能用数量相近推导智能相同。

## 从 CNN 到 Transformer：连接方式改变计算负载

CNN 利用局部连接和参数共享，逐层组合局部模式，感受野随结构加深而扩大。Transformer 则通过注意力建立序列元素之间的联系。文本、音频以及图像 patch 都可以形成序列，但其表示方式与任务目标不相同。

多头注意力让不同子空间分别建立关联，再合并结果。训练时可以并行计算多个位置；自回归生成新 token 时仍存在前后依赖，因此“Transformer 不需要顺序计算”不能不加场景限定。

| 架构 | 典型代表 | 常见任务与机制 |
| --- | --- | --- |
| Encoder-only | BERT 类 | 建立输入表示，用于文本分类、序列标注等 |
| Decoder-only | GPT 类 | 在因果约束下预测下一个 token，逐步生成 |
| Encoder-Decoder | T5 等 | 编码输入，再根据输入表示生成翻译或摘要 |

BERT 主要处理语言表示；图像也可以切成 patch 并编码为序列，进入相应的视觉模型。输入都能写成序列，具体的表示和训练任务仍有区别。

### 上下文窗口不是永久记忆

上下文窗口是一次调用能容纳的 token 数上限，由模型和部署配置决定。窗口能装下一本手册，模型就有机会利用其中的条款；回答质量还要看它能否找到那一段。另开一次不带手册的请求，也不会因为上次读过就自动收到那段内容。

标准稠密注意力的成对交互带来随序列长度平方增长的工作量，实际内存取决于实现。KV cache 避免自回归解码反复计算历史键值，却随上下文和并发增加存储压力。更长窗口需要同时讨论算法、访存和延迟，而不是只报 token 数。

以一个注意力头为例：输入有 512 个 token，完整分数矩阵有 $512\times512=262{,}144$ 个位置；输入加长到 1,024 个，位置数变成 $1{,}048{,}576$。这是整段输入的分数矩阵口径。生成下一个 token 时，只新增一行查询；若缓存里已有 1,024 个位置，新查询需要和已有键以及自己的键比较，共 1,025 项。它可以直接读取历史键值，省去重算它们的工作。整段输入的平方增长与单次解码新增一行，描述的是两个阶段。

## Scaling Law：有条件的经验规律

课堂讨论模型、数据、计算预算扩展与损失下降之间的幂律关系。一个便于理解的简化形式是：

$$
L(C)\approx L_\infty+aC^{-\alpha},\qquad a>0,\ \alpha>0.
$$

它表示在相应实验范围和配套设置下，增加计算预算 $C$ 后损失的可缩减部分按幂律变化。这里是幂律而非指数律；有非零下限时，取对数近似线性对应的是 $L-L_\infty$，不能机械地对所有量取对数。

给公式一组方便手算的数。若 $\alpha=0.5$，计算预算增至原来的 4 倍，能继续降低的部分 $L-L_\infty$ 会乘上 $4^{-0.5}=0.5$。设损失原来是 1.8、拟合出的下限是 1.2，减半的是二者的差 0.6，因此新估计为 $1.2+0.3=1.5$。指数和下限都是给特定数据、模型与训练设置拟合出来的；这里的数字只用于看懂公式。

扩大预算也会增加供电、散热、网络和故障恢复的负担。比较训练方案时，损失曲线回答「多用计算还能改善多少」，系统测量回答「这些计算多久能做完、要花多少钱」。

## MoE 与数值精度：减少什么，增加什么

MoE 的路由器为输入选择少数专家，再加权合并专家输出。总参数量与单个 token 激活的参数量因此不同，计算可以稀疏化，但没有被当前 token 选中的权重仍需在某处存储或加载。

设有 8 个专家，每个 1000 万参数，每个 token 交给其中 2 个。单个 token 在专家层用到 2000 万参数；整层仍有 8000 万参数要放在设备上，这两个数字都没计共享层和路由器。若 8 个专家分散在多卡上，还要把 token 送到被选中的卡。批次里很多 token 都选中同一个专家时，最快的几张卡也要等最忙的那张卡处理完。

课堂讨论了 DeepSeek-V3、R1 及相关技术：MoE 处理稀疏专家计算；MLA 指多头潜在注意力；FP8 混合精度训练在部分计算中使用较低精度。这些技术分别作用于不同环节，分析效率时需要逐项看它们减少了什么开销。

低精度减少数据体积和带宽压力，也带来范围、舍入误差、异常值与硬件支持问题。训练中的混合精度和部署时的权重量化有关联，但不是同一个操作。比较方法时，应在相同任务质量要求下再比较速度和资源。

## AI 自动化设计：生成之后，谁来验证

从专家系统、深度学习到参与设计流程的 Agent，候选生成之后都需要验证环节：把候选设计交给工具检查，再根据反馈修复，才能形成可用的设计流程。

芯片设计可从需求和规格出发，形成结构与逻辑实现，再进入验证、综合和物理实现。AI 可以生成候选设计、解释工具反馈、修复错误，也可能辅助编译器、操作系统和库的开发，但这些是有不同接口与验收标准的任务。

| 环节 | 主要回答的问题 |
| --- | --- |
| 仿真与测试 | 在给定输入和测试覆盖下，行为是否符合预期？ |
| 形式验证 | 在模型、规格和假设内，某项性质是否得到证明？ |
| 综合与时序分析 | 实现的逻辑、面积和时序约束是否满足要求？ |
| 物理设计与功耗评估 | 布局布线、工艺约束和功耗等是否可接受？ |

比如要求一个红绿灯控制器「两个方向不能同时亮绿灯」。仿真可以检查给定时钟和输入下的一段灯色；形式验证可以对模型允许的输入逐一覆盖这条规则。是否真的来得及在每个时钟周期内切换，要另看时序分析。这几项验收各有输入和判据。

把规则写成对四种灯色组合的检查，每种灯色用 `False`、`True` 表示灭、亮。两边同亮是这张真值表里唯一失败的一行。若控制器还保存上一拍的灯色，就要进一步检查从初始状态可到达的各拍；枚举一张静态真值表并没有检查状态转换。

```python
from itertools import product

lamp_states = list(product((False, True), repeat=2))
unsafe = [(east, north) for east, north in lamp_states if east and north]
assert unsafe == [(True, True)]
```

AI 设计芯片的案例中，自动完成的阶段、人工参与程度、验证覆盖、工艺和性能指标共同决定了结果的含义。生成一段设计代码的耗时，只占完整交付流程的一部分。

## 工业软件与程序验证

CAD 面向辅助设计，CAE 面向工程分析，EDA 面向电子设计自动化。它们的重要积累包括求解器、几何和材料模型、约束处理、工程数据与工作流程。学习型代理模型有机会加速部分计算，但是否替代某个环节，需要检验精度、泛化范围、守恒等约束及工程认证要求。

理解程序、数据和接口，是判断自动生成结果是否可信的基础。模型结构、低精度和长上下文对速度、内存的影响，也取决于具体负载。
