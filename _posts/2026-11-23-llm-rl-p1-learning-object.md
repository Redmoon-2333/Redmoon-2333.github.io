一个系统用了 Qwen，又用了强化学习，训练之后正确率提高了。要读懂这个结果，首先需要知道：**奖励最后改变了谁的参数？**

这里沿用一个贯穿系列的教学任务。侦察员 A 看见两座桥的限重，运输员 B 看见货车重量并负责选桥。本例约定每局恰有一座桥可通行，可通行桥在两侧等概率出现，B 单凭重量无法判断是哪一侧。成功奖励 1，失败奖励 0。这是用来解释方法的例子，后面的实践篇会另行介绍实际运行过的任务与结果。

## 1. 先把强化学习的几个词放进任务

| 概念 | 在选桥任务中的含义 |
|---|---|
| 环境状态 | 两座桥限重、货车重量、当前轮次等完整信息 |
| 局部观察 | A 只看到限重，B 只看到重量 |
| 动作 | A 发送消息，B 选择桥；也可以把“请求复核”设计成动作 |
| 策略 | 在当前可见信息下，选择各动作的概率分布 |
| 轨迹 | 从看到信息、发送消息到选择桥、得到结果的整段经历 |
| 奖励 | 环境对某一步或最终结果给出的数值 |
| 回报 | 从当前时刻开始，后续奖励按约定累积后的数值 |

策略不是某一个固定答案。例如在当前观察下，B 以 0.7 的概率选北桥、0.3 的概率选南桥，这两个概率就是策略的一次输出。Actor 是产生动作分布的模型；PPO、MAPPO 是更新策略的方法。

如果当前所有奖励都在终点发放，且折扣系数取 1，本局回报就等于最后的 0 或 1。如果每走一步还要付成本，或者使用折扣，回报就需要把这些项一起算进去。

折扣把更远的奖励乘上更小权重。例如立即奖励 0.2、下一步奖励 1，折扣取 0.9，当前回报就是 `0.2 + 0.9×1 = 1.1`。训练目标通常是让许多局的预期回报提高。

## 2. 第一种搭法：Qwen 冻结，小 Actor 学决策

A 的小型 Actor 决定“报告北桥”“报告南桥”还是“完整报告”；冻结 Qwen 把选择转成自然语言。B 的 Actor 读取自己的观察及可获得的消息表示，选择桥。

训练时可以用已经学过的 MAPPO：Actor 依据各自可见的信息行动，训练阶段的 Critic 使用协议允许的联合信息估计价值。梯度更新小型策略网络和 Critic；Qwen 的权重保持不变。

这里的信息链是：

```text
局部观察 → 小 Actor 选动作 → 冻结 Qwen 组织文本
         → 队友接收 → 环境给奖励 → 更新小 Actor / Critic
```

Qwen 可以生成不同的消息，因为输入与小 Actor 的选择在变化。**输出变化和参数学习是两回事。** 这时系统准确率变高，支持整个决策流程改善；单凭这个指标，还不能分别判断 A、B 两个 Actor 各自改善了多少。

LLM-MCA 属于理解这类结构的一个入口：语言模型读取联合轨迹并提供个体反馈，下层策略接受训练。其归档原文采用 Gemma-7B 与 Double DQN；用 Qwen、MAPPO 讲解是教学替换。

## 3. 第二种搭法：Qwen 自己就是 Actor

让 A 的 Qwen 直接生成消息，让 B 的 Qwen 直接生成答案。此时输出的每个 token 都是从词表分布里选出的离散动作。

设输入为 $x$，生成三个 token：$y_1,y_2,y_3$。整段输出概率为：

$$
\pi_\theta(y\mid x)
=\pi_\theta(y_1\mid x)
\pi_\theta(y_2\mid x,y_1)
\pi_\theta(y_3\mid x,y_1,y_2).
$$

这里 $\theta$ 是待训练参数，$\pi$ 是策略分布。实际训练常使用对数概率，把连乘变成相加：

$$
\log\pi_\theta(y\mid x)
=\sum_t\log\pi_\theta(y_t\mid x,y_{<t}).
$$

可以把小 Actor 的“北桥/南桥”两个输出，想成扩展为 Qwen 的整个词表。生成一句话相当于连续做了很多次选择。

环境判定桥能否通过可以是普通 `if` 规则。规则自身无须可导；策略梯度通过模型给实际动作的概率回传：

$$
L_{\text{actor}}=-A\log\pi_\theta(y\mid x).
$$

$A$ 是优势，表示这次结果相对预期好多少。若本局奖励为 1、参照价值为 0.6，教学优势就是 0.4。优化器据此调整生成分布。共享参数下，一次批量更新会同时影响许多输出，不能把正优势理解为“每个 token 更新后都必然涨概率”。

## 4. 用四选一的小代码看见梯度

下面把词表缩成四个候选动作，只检查梯度路径。它没有加载 Qwen，也没有完成一个训练任务；其作用是把上面的损失变成可观察的数值。

```python
import torch
from torch.distributions import Categorical

logits = torch.nn.Parameter(torch.zeros(4))
optimizer = torch.optim.SGD([logits], lr=0.1)

action = torch.tensor(1)          # 这局实际选择了第 1 号动作
advantage = torch.tensor(0.4)     # 评分在 Actor 更新中当作固定权重

dist = Categorical(logits=logits)
loss = -dist.log_prob(action) * advantage.detach()

optimizer.zero_grad()
loss.backward()
print("各 logit 的梯度：", logits.grad)
optimizer.step()
print("更新后的动作概率：", logits.softmax(dim=-1).detach())
```

初始概率都是 0.25。所选动作的 logit 梯度为 −0.3，其余为 0.1；梯度下降后，第 1 号动作概率约为 0.2576。负号来自“最小化负收益”，不是给好动作惩罚。

梯度描述损失随参数微小改变而变化的方向；梯度下降沿相反方向改参数。上面的 `logits` 是进入 softmax 之前的分数，softmax 把它们变成总和为 1 的概率。

直接写 `loss = -reward`，如果 `reward` 是规则产生的普通数值，它没有连接到 Qwen 参数的计算图。缺少的就是上面这个可导的 `log_prob`。

在真实语言模型中，还要对齐“哪个位置的 logits 预测哪个输出 token”，用输出掩码排除提示词与补齐位置。P2 会把这些细节和 PPO 连起来。

## 5. 第三种搭法：主干冻结，LoRA 在学习

全量微调更新 Qwen 的大量主干参数。LoRA 在部分线性层旁加入低秩增量：

$$
W_{\text{eff}}=W_0+UV.
$$

$W_0$ 保持冻结，$U,V$ 接收梯度。最终参与前向计算的有效权重改变了，因此“主干冻结”与“模型行为正在被训练”可以同时成立。

若 $W_0$ 为 $d_{\mathrm{out}}\times d_{\mathrm{in}}$，则 $U$ 为 $d_{\mathrm{out}}\times r$、$V$ 为 $r\times d_{\mathrm{in}}$，其中 $r$ 远小于两个原维度。训练参数量是 $r(d_{\mathrm{out}}+d_{\mathrm{in}})$，低秩结构让这部分参数显著少于完整矩阵。

QLoRA 还会量化存储主干以节省显存，同时训练适配器。它改变资源使用方式，不能代替奖励、数据和策略损失的设计。

| 实际设置 | 被优化的参数 | 应怎样描述 |
|---|---|---|
| 冻结 Qwen＋小 Actor | 小 Actor、可选 Critic | 控制器学习 |
| Qwen 全量策略微调 | Qwen 主干、可选 Critic | LLM 接受 RL 更新 |
| 冻结主干＋可训练 LoRA | LoRA、可选 Critic | LLM 的适配器接受 RL 更新 |
| 只修改提示词或记忆 | 无梯度更新，除非另有训练器 | 输入或上下文改变 |

看代码时，沿着四个位置找：动作由哪个模型产生、损失使用谁的概率、哪些参数有梯度、优化器持有哪些参数。四者对上，才知道论文中的“训练”具体发生在哪里。

## 6. 共同得分之后，还有信用问题

如果 A 发了一条没有被 B 使用的消息，而 B 恰好选对了桥，两人都用正团队优势更新，A 的消息也会收到该样本的正权重。这个做法可以构成团队目标的策略梯度估计；单次奖励却不足以判断某条消息的贡献。

后面的信用分配研究，就是在进一步问：同样的团队结果，怎样让不同角色、不同步骤收到更有用的学习信号？
