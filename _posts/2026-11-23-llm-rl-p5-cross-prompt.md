Qwen 用同一组参数回答许多题。在一道题上更新，会同时改变其他题的输出。这是知识迁移的来源，也是错误模式跨题传播的一条通道。

[P4](/2026/11/23/llm-rl-p4-verifier/) 区分了代理接受与真实正确。本篇继续看这种区别在共享参数下怎样影响研究设计。

## 1. 为什么一题的更新会影响另一题

设题目 A 的损失推动参数沿方向 $g_A$ 改变，题目 B 某个输出的概率对参数也有敏感方向 $g_B$。两者内积可以反映一次小更新对 B 的一阶影响：方向接近时影响较强，正交时较弱，反向时可能相互抵消。

原文用经验切核把这种局部耦合写成可分析的量。它还取决于当前策略概率和步长，因此“某个错误答案有 80 题支持、20 题反对”只是等权直觉，不能直接代替更新方程。

一个可复用的加法方法会受益于共享；一个能骗过多题验证器的固定格式也可能受益。研究需要区分这两种共享。

## 2. “漏洞普适度”已经包含错误条件

Wrong the Same Way 定义每题的错误接受集合：

$$
H(x)=\{y:V(x,y)=1,\ C(x,y)=0\}.
$$

对一个候选输出 $h$，可数它在多少题上属于这个集合：

$$
u(h)=\frac{|\{x:h\in H(x)\}|}{N}.
$$

$N$ 是所考察的题目数。这个量同时需要验证器接受和真实错误两个条件。只计算 $V$，得到的是跨题接受率。

例如 `2+2` 和 `1+3` 的正确答案都是 `4`。把答案 `4` 交换过去，验证器继续接受，完全可以是正确复用。反过来，一个只对特定题起作用的漏洞，也可能在交换后消失。

## 3. 当前 C02 候选：先筛查，再判断怎样更新

C02 暂定研究不完美验证器下的在线抗捷径。现有设想是：从高奖励回答中抽样，把回答交给同批其他题的验证器，取得跨题接受特征，再决定是否需要进一步审计或调整训练权重。

这里有三个分别需要实验回答的问题：

| 环节 | 需要建立的证据 |
|---|---|
| 筛查 | 跨题特征能否区分错误捷径与通用正确答案 |
| 干预 | 使用该特征后，错误输出的学习趋势怎样改变 |
| 净收益 | 在匹配计算预算下，独立任务质量是否改善 |

候选还没有完成 Qwen 在线训练闭环。之前讨论的 5% 是一个抽查比例设想；一次抽查可能对多个题评分，还要经过解析与审计，因此它不等于总成本增加 5%。

## 4. 一个能真正区分解释的实验

先设计三类可控答案：跨题通用的正确规则、跨题通用的错误接受模式、只在单题触发的错误。让它们在训练前的频率和代理奖励尽量匹配，再比较检测分布。

若筛查器只把“共享”当作问题，它会同时惩罚通用正确规则。若它确实识别了错误结构，应该在保留正确复用的同时，更集中地标记假阳性。

在有精确参照的受控环境中，真值用于评价检测器。若方案声称训练时不需要真值，训练器就不能偷读真值标签；数据流与日志中要把二者隔开。

下面是只定义测量量的代码摘录，不是已完成的在线优化器：

```python
def acceptance_rate(accepted_on_targets):
    # 每个元素表示同一回答在一个目标题上是否被代理接受
    return sum(accepted_on_targets) / len(accepted_on_targets)

def false_positive_rate(accepted_on_targets, correct_on_targets):
    # 此处按全部目标题为分母，对应漏洞普适度的离散估计
    false_accepts = sum(
        accepted and not correct
        for accepted, correct in zip(
            accepted_on_targets, correct_on_targets
        )
    )
    return false_accepts / len(accepted_on_targets)

print(acceptance_rate([True, True]))                 # 1.0
print(false_positive_rate([True, True], [True, True]))  # 0.0
```

接受率完全相同的候选，可以有完全不同的错误性质。这就是筛查与真值判断必须拆开的原因。

## 5. 强对照要排除什么

至少保留相同采样与评分预算下的基础策略更新、随机衰减同样数量样本、统一降低学习率或加强 KL，以及可获得的验证器修补方案。

随机衰减用于排除“少学了一点就更稳定”；降低学习率用于排除更新强度变化；修补验证器检验能否用更直接的工程改进解决问题。误伤率需要在通用正确答案上单独报告。

不同论文提供不同条件：Optimistic Verifiers 有外部规则解释参照；Reward Suite Is Leaky 的额外测试仍需审计；Wrong the Same Way 提供受控共享机制。把这些条件写清，才能判断方法在哪一种任务上有可检验的增量。

## 6. 此刻课题推进到哪里

当前已经有文献机制、受控评测思路和待比较方案。下一项有区分力的证据，是交换筛查到底能识别多少错误、又会错伤多少正确复用。结果出来后，再决定是否投入更贵的 Qwen 策略训练。
