界面上的每一步操作，都要求用户从信息中选出重点、辨认含义、记住状态，并判断接下来该做什么。交互设计因此不能只看控件是否存在，也要看它怎样配合人的认知过程。

Day4 以注意、感知、记忆、学习、语言和决策为主线，随后介绍心智模型、执行与评估鸿沟、分布式认知和外部认知。课堂开头还回顾了设计者模型、系统映像与用户模型，并以互联设备的隐私风险引出设计情境；这些内容与前一课相连，课件主体则集中在认知。

## 一、认知与人机交互

课件把认知概括为思考、记忆、学习、走神、决策、看、读、说、写等过程。它既包含快速、依赖经验的反应，也包含需要有意识推理的过程。课件以 **经验性认知（experiential cognition）** 和 **反思性认知（reflective cognition）** 作为高层分类，并用快速与慢速思考举例；两组说法相关，但不宜当成完全等价的分类。（课件第 2-6 页）

| 认知过程 | 与交互有关的问题 |
| --- | --- |
| 注意 | 用户能否在当前情境中看到真正重要的信息？ |
| 感知 | 文本、图标、颜色、声音和触觉反馈是否容易区分？ |
| 记忆 | 用户必须自己记住多少名称、位置和操作规则？ |
| 学习 | 新手能否在合适的帮助下逐步掌握操作？ |
| 阅读、说话与聆听 | 信息是否适合用户的能力、环境和使用方式？ |
| 问题解决、计划、推理与决策 | 用户能否看懂选项、状态及其后果？ |

这些过程会彼此影响。界面呈现方式会改变人注意到什么；注意影响信息如何编码进记忆；已有经验又会影响用户怎样解释新的提示。因此，认知知识的作用不是给用户贴标签，而是帮助设计者判断：可以合理期待什么、用户可能在哪里遇到困难，以及可以用哪些理论与方法改进交互。（课件第 5-6 页）

## 二、注意：让重要信息在合适的时刻出现

注意是人在大量刺激中选择当前关注对象的过程。集中注意帮助用户处理与任务相关的信息，但也限制了他们同时追踪多个事件的能力。视觉弹窗、声音和环境变化都可能竞争注意资源。（课件第 7-17 页）

### 信息组织影响查找

课件比较了两种信息密度相同的酒店列表布局：一组信息紧凑堆叠，另一组按类别纵向分组。课件引用 Tullis（1987）的结果称，查找用时分别为平均 5.5 秒和 3.2 秒；差异与分组和间距有关，而不是信息量减少。（课件第 9-11 页）

这个例子说明，信息架构会改变人找到目标的难易程度。颜色、间距、边界、顺序和分组可以帮助扫视；但如果界面塞入过多信息，用户仍可能难以确定应该先看哪里。课件引用的多任务研究也提醒，频繁切换可能使人丢失思路、出错或重新开始；与当前任务有关的线索和无关干扰，影响并不相同。（课件第 12-14 页）

### 设计启示

- 在当前任务需要信息时突出它，而不是让所有内容始终争抢注意。
- 用颜色、顺序、间距、下划线、步骤提示等方式建立层次；关键区别不要只靠颜色表达。
- 避免把过多信息堆在同一页面，并为中断后的返回保留清晰线索。
- 对重复监控任务，可考虑让系统按用户设定的规则处理；用户仍应看得懂系统状态，并能在需要时介入。
- 驾驶等高风险情境中，注意力保护优先。课件明确以“开车时不要使用手机”提醒设计者，免提或语音方式也不能消除所有分心风险。（课件第 15-17 页；课堂案例）

## 三、感知：信息要能被看见、听清和区分

感知是人从环境中获取信息并形成体验的过程。文本需要易读，图标需要容易区分；边界与留白有助于把相关信息组织成组，声音需要清楚且彼此可辨，触觉反馈也应有节制。（课件第 18-23 页）

课件用查找酒店信息的页面对比颜色编码与边框分组，并引用 Weller（2004）关于分组信息更容易定位的结果。另一个页面练习比较不同文字与背景搭配的可读性。它们共同指向一个设计问题：相同内容并不保证相同的可感知性，布局和呈现方式会影响用户发现信息的速度。（课件第 19-23 页）

实际设计不能把课件中的颜色例子直接当作所有屏幕和用户都适用的固定规则。应结合文字与背景的对比、字号、环境光和用户能力检查可读性；确定、取消等重要操作也应使用文字、形状或位置等冗余线索，避免用户只能依赖颜色判断。

## 四、记忆：让界面支持识别，而非强迫回忆

记忆涉及信息的编码与提取。人不会保留环境里的所有内容：注意和解释会影响哪些信息被编码，情境则会影响之后能否提取。熟悉的人换到陌生场景时可能一时难以辨认，说明记忆并非脱离情境独立运作。（课件第 24-27 页）

课件强调，人在很多交互中更容易从可见选项中识别目标，而不是从头回忆名称或命令。菜单、图标、浏览历史和标签能够提供识别线索。文件越来越多时，只靠记住文件名和路径会变得困难；时间、类别、创建者等元数据可以帮助查找，但元数据本身也需要被组织得容易理解。（课件第 28-33 页）

密码管理器是把部分记忆负担交给外部工具的例子：用户不必分别记住每个账户的复杂密码，而是使用管理器保存和填入凭据。类似地，日历、提醒和搜索功能也可以支持记忆。但“增加标签”不自动等于更好检索；若用户必须记住何时创建、怎样命名每一个标签，负担只是换了位置。

设计可以据此减少冗长流程、稳定常用入口，并提供文件夹、分类、时间、标记和搜索等互补线索。课件还提到 Henkel（2014）关于拍摄物体与之后记忆表现的研究；它应作为特定实验现象理解，不宜扩大成“拍照普遍损害记忆”的结论。（课件第 24-33 页）

## 五、学习：在探索与引导之间取得平衡

课件区分偶然学习与有意学习，并指出有意学习通常需要投入更多努力。人们往往更容易在操作和反馈中学习，但这不意味着所有功能都应让用户自行摸索。（课件第 34-35 页）

界面可以同时支持探索与约束：允许用户尝试，同时在学习阶段缩小可操作范围、按步骤提示当前目标，并把概念与对应表示联系起来。课件用 Word 助手和受限操作的教程作为对比，说明帮助形式应服务于学习任务，而非一次性展示大量说明。

新手引导可以每次聚焦一个核心操作，给出及时反馈和必要提示。提示应让用户知道下一步目标，也应避免替用户完成整段任务；当用户已经熟悉功能时，帮助入口仍应可查找，但不必持续打断。

## 六、阅读、说话与聆听：为不同能力和情境保留入口

课件指出，人们阅读、说话和聆听的便利程度各不相同。有些人偏好听觉信息，阅读在某些任务中可能比聆听更快；听觉输入对部分用户可能更省力，阅读障碍者则可能难以识别或理解书面词语。这些是用户差异，不构成“语音总比文字好”或相反的结论。（课件第 36-38 页）

语音界面可以支持口头查询，语音合成可以朗读文本，自然语言系统也可以通过文字问答。设计上，语音菜单和说明应简短，合成语音要清晰，并提供放大屏幕文字的方式。对于语音识别或意图理解可能出错的场景，保留可见的文字确认和修改入口，有助于用户核对系统理解。

## 七、问题解决与决策：把比较过程放到界面上

计划、推理和决策通常涉及反思性认知：用户要考虑要做什么、有哪些选项，以及各选项可能产生什么后果。地图、书籍、纸笔、图表和与他人的讨论，都可能成为完成思考任务的外部支持。（课件第 39-41 页）

课件以数据可视化辅助决策为例，并建议让帮助页面易于访问、常用功能简单易记。界面可以把重要信息放在容易比较的位置，让用户查看细节时仍能理解整体。课件第 42 页提出“应用程序是否让人更依赖他人意见”的讨论题；它是课堂问题，不是课件已经证明的普遍结论。

## 八、心智模型与两类鸿沟

课件第 43 页把心智模型、执行与评估鸿沟、分布式认知、外部与具身认知列为理解用户行为的认知框架。后续页面具体展开了心智模型、两类鸿沟、分布式认知和外部认知；具身认知在课件中仅列出名称，没有单独说明。

### 心智模型：用户如何理解系统

人会在使用和学习系统的过程中形成对其工作方式的理解，即 **心智模型（mental model）**。它既可能包括“下一步该怎么操作”，也可能包括“这个系统大致如何工作”。用户会据此推断系统会怎样响应；模型可以很浅，也可以包含较深入的机制理解。（课件第 43-48 页）

恒温器和电烤箱的例子说明，“把数值调到最高就会更快完成”的“越大越快”类比，可能不符合设备实际控制方式。电梯或行人按钮被连续按下，也可能来自“多按几次会更快”的不准确理解。用户通常不愿为了每个设备先研究内部机制，因此界面应通过清楚的说明、情境帮助、透明状态和可辨认的操作线索，减少用户只能靠猜测建立模型的情况。

课堂开头回顾的设计者模型、系统映像和用户模型与这里相关，但不是同一个概念：设计者模型是设计意图，系统映像是用户能接触到的界面、行为和说明，用户模型则是用户据此形成的理解。设计意图不会自动传到用户心里，系统呈现出来的状态和反馈是两者之间的重要媒介。

### 执行鸿沟与评估鸿沟

课件用两种问题说明用户与系统之间的鸿沟：**执行鸿沟**是“我该怎样使用这个系统来完成目标？”；**评估鸿沟**是“系统现在处于什么状态，刚才的操作产生了什么结果？”清楚的操作映射、可见反馈和状态信息，有助于缩小这两类差距。（课件第 49 页）

![执行鸿沟与评估鸿沟](/assets/img/hci-day4/mental-model-gulfs.png)

*图 1：课件第 49 页示意。左侧评估鸿沟关注用户怎样理解系统状态，右侧执行鸿沟关注用户怎样把目标转化为操作。*

例如，提交表单后只显示一个旋转图标，用户可能不知道系统正在处理、已经成功还是失败；若页面说明进度、结果和下一步可用操作，用户便更容易判断是否需要等待或重试。

### 信息处理模型：分析流程的简化视角

课件用一个四阶段示意描述输入到输出的过程：**编码 → 比较 → 反应选择 → 反应执行**。（课件第 50 页）

| 阶段 | 在交互中的分析问题 |
| --- | --- |
| 编码 | 用户注意到并理解了哪些输入？ |
| 比较 | 用户依据什么已有知识或标准解释信息？ |
| 反应选择 | 用户决定采取哪项操作了吗？ |
| 反应执行 | 操作能否顺利完成，系统是否给出反馈？ |

这是一种帮助分析人类表现的简化模型，不代表每个真实任务都严格按四个互不重叠的步骤线性完成。它的价值在于让设计者逐段检查：困难可能发生在看见信息、理解信息、选操作或执行操作中的哪一处。

## 九、分布式认知与外部认知

### 分布式认知：认知活动跨越人和工具

**分布式认知（distributed cognition）** 关注认知活动如何分布在不同个体、工具和内部或外部表征之间。信息会在人、显示器、纸张、仪表和交流过程中转换，不只存在于某一个人的头脑里。（课件第 43、51 页）

![驾驶舱中的分布式认知示例](/assets/img/hci-day4/distributed-cognition-cockpit.png)

*图 2：课件第 51 页案例局部。空管指令、飞行员操作、仪表状态和另一位飞行员的观察共同构成任务中的信息传递过程。*

分析复杂任务时，应同时看参与者掌握什么信息、工具如何呈现状态、信息怎样交接，以及交接中可能发生什么误解。单独改善某一个屏幕，不一定能解决整个协作流程的问题。

### 外部认知：让外部表征帮助记忆与思考

**外部认知（external cognition）** 研究人如何借助地图、笔记、图表等外部表征完成任务，以及这些表征怎样扩展可进行的认知活动。（课件第 52-57 页）

课件区分了几种常见方式：

- **认知卸载（cognitive offloading）**：用日历、提醒、便笺、清单等减少记忆负担。外部记录可以提醒“有一件事要做”“要做什么”或“何时完成”。
- **计算卸载（computational offloading）**：借助纸笔或计算器完成计算。工具和表达方式都会影响任务难度。
- **标注（annotation）**：通过划线、打勾或删除线修改既有信息表示。
- **认知追踪（cognitive tracing）**：在外部空间移动或重新排列对象，例如拼字游戏中的字母或纸牌排序。

这些做法不是把思考交给工具后就不必判断，而是把记忆、计算和信息重组的一部分放在可见、可操作的表征上。对应的设计机会包括可编辑的清单、稳定的提醒、便于比较的图表和容易恢复的标注；用户仍需要理解信息是否可靠，以及操作之后发生了什么。

## 十、从认知知识回到交互检查

| 设计问题 | 可以检查的交互细节 |
| --- | --- |
| 重要信息是否会被注意到？ | 是否符合当前任务情境，是否被无关提示淹没？ |
| 信息是否容易感知？ | 文本、图标、颜色、声音和触觉提示是否清楚且可区分？ |
| 操作是否依赖用户记忆？ | 是否提供可见选项、稳定入口、历史记录或合适搜索？ |
| 新手能否学会？ | 是否能逐步尝试、获得反馈，并在需要时找到帮助？ |
| 用户能否理解系统？ | 操作映射、状态变化和错误恢复是否清楚？ |
| 复杂任务是否得到外部支持？ | 图表、清单、提醒、标注和协作信息是否能辅助判断？ |

注意、感知、记忆、学习和决策不是彼此孤立的检查项。一次操作可能同时要求用户发现信息、理解含义、调用记忆并推断结果。把这些认知要求落到具体任务和界面反馈上，才能判断设计是否真正支持了用户。
