一句“设备暂时不可用”包含语义，一份派单方案还要满足技能、区域权限、工序依赖和成员时间。让语言模型一次性完成所有环节，与让它抽取事实再交给求解器，是两种可以直接比较的设计。

这组实验使用冻结模型，主要检验接口与任务分解。它们帮助确定哪里值得训练，当前没有用派单奖励微调这些 LLM。

## 1. 故障之后，不一定要全队重排

作者公开调度数据的复算与本地模拟比较了固定分工、相信报告、校准后改派等策略。

办公室没有故障时，固定分工代价为 10.51，校准后改派为 12.34；长故障时，两者为 56.61、36.71。是否改派取决于等待损失能否覆盖调整成本。

这属于公开数据与模拟调度分析，没有运行真实机器人。作者统计按任务等权的正确性为 0.948276，若改用合并记录数加权，会得到不同数值。

## 2. 会分类延误，不等于知道报告可信

32 条不同故障通知中，3B 模型换选项顺序后的正确数为 18/32、26/32，词法规则为 30/32。后续远程模型的通知重测为 31/32、32/32。

分类任务回答的是“通知说了哪种延误”，并未验证延误是否真实，也未辨别两条通知是否来自同一份复制报告。三个问题应分别设计标签。

另一组方案复核只有 40 个已判正确方案和 7 个未评分方案，没有已判错误样本。模型把其中 38 个正确方案送审，可以算误报 95%；坏计划召回率缺少分母。

## 3. 单字母派单与允许推理，结果会不同

96 条资源约束派单请求中，限制只输出字母时，远程模型答对 65 条、本机 3B 答对 28 条，规则求解为 96 条。允许远程模型核对条件并给出推理后，同批达到 96/96。

这说明输出协议本身是重要变量。不能把字母受限结果当成模型在任何提示下的能力上限。

## 4. 五工序：抽取＋求解的比较

新任务包含五道工序、四名成员、技能与区域权限、速度和前置依赖。规则规定按 T1–T5 的拓扑次序排入每人的日程，目标是最小完工时间。

| 方法 | 40 道新题结果 | 输入＋输出 token 约值 |
|---|---:|---:|
| 大模型直接派单，合并截断重跑后 | 39/40 | 2,016/题 |
| 大模型抽取 JSON＋精确枚举 | 40/40 | 619/题 |
| 按最快合格成员贪心 | 25/40 | 0 |

表中 2,016 是补跑后保留回复的均值。计入被替换的原调用和补跑，40 次原调用加 13 次补跑共 111,180 token，即实际记录成本 2,779.5 token/题。枚举求解还使用 CPU，表中的 token 只计模型调用。

旧直接派单表为 27/40，不能越过后续截断修正继续使用。中档模型两次抽取也都正确且一致，每次约 1,774 token/题；该配置没有获得与 large 抽取相同的 token 节省。

3B 的完整抽取为 0/40，37 题抽错前置依赖。精确求解器能解决收到的结构，却不能自行知道哪条抽取事实与原文不符。

## 5. 求解器的核心逻辑

下面摘出实际枚举流程。`job["tasks"]` 保存每道工序的 `id`、`skill`、`zone`、`work`、`after`；成员有 `name`、可用技能/区域和 `speed`。

```python
import itertools

def qualified(task, worker):
    return (
        task["skill"] in worker["skills"]
        and task["zone"] in worker["zones"]
    )

def solve(job, makespan):
    names = [worker["name"] for worker in job["workers"]]
    best = None
    for assignment in itertools.product(
        names, repeat=len(job["tasks"])
    ):
        plan = {
            task["id"]: name
            for task, name in zip(job["tasks"], assignment)
        }
        finish_time = makespan(job, plan)
        if finish_time is not None:
            if best is None or finish_time < best[0]:
                best = (finish_time, plan)
    return best
```

`makespan` 是实际程序的资格检查与排程函数：不合格返回 `None`；合法工序的开始时间取“成员空闲时间”和“所有前置工序完成时间”的最大值。

四名成员、五工序共有 $4^5=1024$ 种分配，当前规模可以全枚举。这里的最优性针对上述固定排程规则，不是任意工序数、任意排序的通用调度最优解。

## 6. 大模型拆题，小模型执行：步骤越细不一定越好

沿用 E4 的 400 道数学题，大模型生成 2–5 个子问题：

- 把计划作为提示，小模型由 84.25% 到 88.25%，改对 38 题、改错 22 题。
- 要求小模型严格逐步执行，降到 62.5%，常见错误是把子问题对应到了错误的量。
- 只改派第一个分歧步骤，整体为 84.0%；97/137 是失败条件内的救回数，还使用了大模型参考轨迹。

把任务分段只是改变接口。需要看接收者能否理解每段、局部答案能否正确传递、错误是否传播，而不能由“计划写得很清楚”推断执行一定更好。

## 7. 复核没结束，能不能先开工

另一个模拟枚举复用了 40 张工单，研究依赖尚未核实时，是否存在对所有候选依赖图都安全的首派。等待设为 2 工时，14 张多候选工单中，相对最强零误派对照多赢 1 张，平均多省约 0.071 工时，未过预设门槛。

这里的工时是任务模拟单位。它不是语言接口响应的实际等待时间。

语言理解、可行性与执行收益分别测量后，才能决定下一步该训练抽取器、改提示、换求解器，还是重新选择更有信息量的任务。
