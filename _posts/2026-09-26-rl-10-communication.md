> 前几章解决的都是“信息已经在我手里，怎么学”：值分解把团队 Q 拆开，反事实基线把功劳分清。但有一种信息缺口，任何学习算法都补不上——答案压根不在我的观测里。这时唯一可能的出路是让队友告诉我。本章要回答的不是“怎么让智能体学会说话”，而是一个更前置的问题：**什么时候通信才可能提供本地观测拿不到的额外信息**。要回答它，光看“加了通信分数更高”不够，因为更高的分数可能来自更深的网络；需要一个能算出上限的环境，把“信息”和“容量”两个因素拆开。

## 一 · 核心问题：信息不在本地时，上限在哪

多智能体设置里，“通信有没有用”通常被当成一个定性问题：加一个消息通道，成绩涨了，就说通信有用。这个推理有漏洞——加通道往往同时加深了网络、增加了参数，成绩的增量说不清来自信息还是来自容量。要让“通信的价值”成为一个可测量的量，需要满足两个条件：

1. **存在一个可计算的信息上限**：任何只依赖本地观测的方法，无论网络多大、训练多久，成绩都撞在一个天花板上；这个天花板要能用期望值算出来，而不是猜的。
2. **存在一个尽量只关掉信息的对照**：消融版与通信版名义参数量、深度完全一致，差别只在消息是否置零——名义相同不等于有效容量相同，第六节回到这条边界。

开关谜题（`RiddleEnv`）就是为了这两个条件设计的：它的无通信成功率上限是可计算的 50%，它的等参数消融（`commnet_nomsg`）只把消息置零，其余结构不变。本章的实测设计围绕这两个量展开——**通信是否提供额外信息，以实测能否突破 50% 为准**。

## 二 · 谜题构造：答案只有智能体 0 看得到

谜题在 9 个格子（0–8）上进行，第 3 格是墙，把场地切成左右两半。每局开始时正确答案从 {4, 6} 中随机取一个，**答案只写进智能体 0 的观测**；智能体 1 从第 5 格出发，负责去踩开关。观测是 3 维向量 `[自身格子/8, 自身编号, 答案特征]`，其中智能体 0 的答案特征是 0.0（答案为 4）或 1.0（答案为 6），智能体 1 恒为 0.5——不是“看得模糊”，而是**零信息**：无论答案是什么，智能体 1 的观测分布完全相同。

奖励与终止口径：

| 事件 | 奖励 | 终止语义 |
|---|---|---|
| 智能体 1 踩中正确开关 | $+10$（另计每步 $-0.1$） | `terminated`，success，真实终止，不 bootstrap |
| 智能体 1 踩中错误开关 | $-5$（另计每步 $-0.1$） | `terminated`，fell，真实终止，不 bootstrap |
| 25 步仍未作答 | 累计每步 $-0.1$ | `truncated`，人为上限，可 bootstrap |

三个数就是本章的全部算术素材：$+10$、$-5$、25 步。“踩错”是 `terminated` 而不是 `truncated`——答错是任务的结局，不是时间用完，与第 6 章的口径一致。

## 三 · 50% 上限的推导：作答与不作答的取舍

![开关谜题的无通信上限：答案只在智能体 0 观测中，智能体 1 从 5 出发，本地观测方法的成功率天花板为 50%](/assets/img/rl-practice/07_riddle_ceiling.png)

**上限为什么是 50%。** 一个只依赖本地观测的方法（含任意深度的网络、任意大的回放），决定智能体 1 走向 4 还是 6 的全部依据是它的观测序列。智能体 1 的观测中与答案有关的维度恒为 0.5，另外两维是自身格子与编号；墙把智能体 0 挡在左半边，两者不会相遇，智能体 1 的位置只由它自己的动作决定。答案是均匀的 0/1 掷硬币，智能体 1 的整条观测序列对这个硬币零信息。于是无论策略多复杂，$\Pr[\text{踩对}] \le \Pr[\text{猜中硬币}] = 0.5$——只有每次都走到开关作答时取等，沉默与超时只会把成功率拉得更低。成功率的期望上限就是 **50%**：信息论意义上的天花板，更多样本、更大网络都改变不了输入里没有的信息。

**期望回报怎么算。** 假设一个无通信策略第一步就作答（智能体 1 在 5，走一步即可到 4 或 6），两种结局：

$$0.5 \times (10 - 0.1) + 0.5 \times (-5 - 0.1) = 0.5 \times 9.9 + 0.5 \times (-5.1) = 2.4$$

对照组是“永不作答”：拖满 25 步被截断，每步 $-0.1$，合计 $25 \times (-0.1) = -2.5$。

$2.4 > -2.5$，所以在本环境的奖励结构下，**盲猜优于沉默**——即使一半概率吃 $-5$，期望仍是正的；而等待的代价是确定的负数。这解释了无通信方法的合理行为：它应该“随便押一个”，并且这个行为的期望回报 2.4 就是它的回报上限，恰好对应 50% 成功率。反过来看，$2.4$ 与“信息完备时猜对”的 $9.9$ 之间有 7.5 的差——**这就是通信可能争取的空间**。若均在第一步作答，成功概率 $p$ 对应期望回报 $15p-5.1$；存在等待或超时时，还须同时计入局长和失败类型。成功率超过 50% 本身不保证回报超过 2.4。

$2.4$ 和 $-2.5$ 都是“每步只扣 $-0.1$”的奖励结构下的算术，换一组奖励（比如把踩错改成 $-20$）取舍就会反转。50% 上限则只依赖“答案均匀且观测零信息”，与奖励数值无关：**成功率的上限和回报的上限是两个不同的量**。

## 四 · 通信机制：同步轮次、消息投影与残差更新

实现是 `rlpractice/algos/marl/comm.py` 中的 `CommQNet`，结构为“编码 → $R$ 轮（聚合消息 + 残差更新）→ Q 头”：

1. **编码**：$h = \mathrm{ReLU}(W_e o + b_e)$，每个智能体把 3 维观测映到 64 维隐状态。
2. **消息投影**：$b_i = W_m h_i$，每个智能体把当前隐状态投影成一条 64 维广播。
3. **聚合**：$c_i = \frac{1}{n-1}\sum_{j \neq i} b_j$，取队友广播的均值（实现里用 `(b.sum - b) / (n-1)`，去掉自己）。
4. **残差更新**：$h_i \leftarrow h_i + \mathrm{MLP}([h_i; c_i])$，消息与自己的状态拼接后过两层 MLP，结果加回原状态。

**同步轮次**是这里最容易做错的细节：第 $k$ 轮聚合的消息必须来自队友**上一轮**结束时的隐状态，而不是同一轮内“先广播再接收”的实时值——后者要求轮流执行，会在计算图里引入对更新顺序的依赖。最初的实现用的是一个静态缓存（编码后算一次广播就不再更新），没有真正的轮次；本版改为每轮重新投影，第 1 轮的 $c$ 来自编码输出，第 2 轮的 $c$ 来自第 1 轮更新后的隐状态，共 $R=2$ 轮。测试 `test_commnet_messages_come_from_teammates_previous_state` 手算核对了这一点：按“编码 → 投影 → 队友均值 → 残差 → Q 头”手工走一遍，输出与 `net(obs)` 在 $10^{-6}$ 容差内一致。

## 五 · 值学习：VDN 式联合 summed-Q TD

值学习直接沿用第 7 章的 VDN 式组合：对联合经验取各智能体实际动作的 Q 值求和，去回归一个联合 TD 目标。

$$y = r + \gamma (1-d) \sum_i \max_{a_i'} Q_i^-(o_i', a_i'), \qquad L = \mathrm{Huber}\Big(\sum_i Q_i(o_i, a_i),\; y\Big)$$

目标端各自取 $\max$ 后求和，预测端对实际联合动作求和，Huber 损失作用在**联合 summed-Q** 上——这是 VDN 的形式，不是 IQL 的逐智能体回归（对照第 6 章）。$d=1$ 仅在 `terminated`（踩对或踩错）时成立，25 步 `truncated` 照常 bootstrap。

本方法的名称是 **“CommNet 式通信 + VDN 值学习”**：它借用了 CommNet 的消息聚合结构（广播、取均值、残差更新），值学习则是 VDN 式联合 TD。教学小环境上的结果是**机制演示**，口径与全系列一致，不复现 CommNet 原论文的训练方式与实验设定。

## 六 · 消融设计：等名义参数、等轮数的零消息对照

零消息对照要等名义参数、等轮数，只把消息置零；“通信是否有用”的结论取决于这组对照有多干净。

`commnet_nomsg` 在 `use_message=False` 时把聚合消息置为 `th.zeros_like(h)`，保留同样的模块、两轮残差更新和 Q 头。两版名义参数量均为 **29,443**，但零消息分支不执行 `bcast` 投影，消息相关权重不再以相同方式参与计算和获得梯度。**名义参数相等不等于有效容量相等**。

为什么必须这么设计：最初的实现把 `comm_rounds=0` 当作无通信对照，而 0 轮意味着**编码后直连 Q 头**——网络深度、非线性变换次数、参数量全部跟着变少。那样测出的差值是“通信 + 深度”的混合贡献，无法归因：通信版赢了，可能是消息有用，也可能只是它多两层 MLP。消融的职责是隔离变量，而 `comm_rounds=0` 把深度一并改变了。

三个测试固定住这条性质：

- `test_commnet_and_nomsg_have_identical_parameters`：两版参数量逐一相等，任何未来改动若只砍一侧的层会立刻被它拦下；
- `test_nomsg_output_independent_of_injected_messages`：向 `commnet_nomsg` 注入两组不同随机消息，输出逐位相同（消息被完全忽略）；同样的注入打到通信版，输出显著不同——确认零消息输出不依赖外部消息；
- `test_commnet_messages_come_from_teammates_previous_state`：同步轮次的手算核对（见第四节）。

这组对照比直接删掉通信轮更接近隔离信息通路；若要进一步区分信息与容量作用，可增加保留活跃变换的自消息或打乱消息对照，并在相同预算下测试。

## 七 · 实测

协议按系列统一口径：预算 50,000 联合步（每步两个智能体各动作一次、计 1 环境步，口径定义见第 6 章第四节），训练种子 0–4（5 个），每 10% 预算验证一次（评估种子 10000+），最终测试用贪心策略 100 局（评估种子 20000+），误差带为跨种子样本 SD。对照三组：通信版 `commnet`、等参数零消息版 `commnet_nomsg`、以及同一谜题上的独立 Q 学习 `riddle/iql`（无通信的神经基线，代表“本地观测 + 容量”能做到的水平）。

| 方法 | 测试成功率 | 测试平均回报 ± 跨种子 SD | 验证成功率（首个 → 末个验证点） |
|---|---|---|---|
| `commnet`（通信） | **100.0%** | 9.900 ± 0.000 | 100.0% → 100.0% |
| `commnet_nomsg`（等参数零消息） | 20.0% | −0.540 ± 2.736 | 20.0% → 20.0% |
| `riddle/iql`（独立学习） | 11.0% | −1.370 ± 2.527 | 20.0% → 10.8% |

**通信突破了 50% 上限。** `commnet` 在 5 个种子上全部达到 100%，而两个无通信对照分别停在 20.0% 与 11.0%，都远低于 50%——信息确实经由消息从智能体 0 传到了智能体 1。

- **无通信版连 50% 都不到**。50% 是“每次都作答”情形下的正确率上限，不是下限；实测 20.0% 与 11.0% 说明它们多数回合**根本没走到开关**（`commnet_nomsg` 超时率 60%，`riddle/iql` 80%），自然低于盲猜的期望。
- **回报也要按同一口径读**。第三节算出“必答时盲猜的算术期望 2.4”，而 `commnet_nomsg` 实测 −0.540——差在超时局每局 −2.5 的拖累；两者口径不同，一个假设必答，一个包含沉默。

## 八 · 易错点

**一、把 50% 上限当环境噪声。** 上限是可推导的信息约束：智能体 1 的观测对答案零信息，成功率期望最多为 0.5。把它当“随机性大、需要更多种子压噪声”是误解——再多种子只会把实测成功率估得更准，不会让它越过 50%。它是**判据线**：跨过它才说明通信提供了信息。

**二、把“会通信”当“通信有用”。** 通信版跑通了、消息在流动，都不构成“通信有用”的证据。证据只能来自对照：等名义参数的 `commnet_nomsg`（把消息置零）+ 同谜题的 `riddle/iql`（隔离学习算法）。少了对照，“通信版成绩好”可能只是网络更深或调参更细。

**三、把多 agent 对话当 MARL。** 判据见第 6 章易错点一：看有没有策略在训练中被奖励信号改写。本章的“通信”正是学出来的——消息由网络参数生成，聚合方式由梯度塑造，终点是 TD 误差。

**四、跨环境比较回报。** $2.4$、$-5.1$、$9.9$ 都是谜题奖励结构下的数字，与走廊的 $+10$、导航的缩放奖励没有可比性。跨环境不排名；本谜题内的所有比较必须同预算、同种子、同评估协议。

## 代码实现

对应 `复现包 rlpractice/algos/marl/comm.py`（完整实现见复现包）：

```python
def forward(self, obs, messages=None):
    """obs: (B, n, obs_dim)；messages: 可选 (B, n, hidden) 直接注入的聚合消息。"""
    h = self.enc(obs)                                   # (B, n, h)
    for cell in self.cells:
        if not self.use_message:
            c = th.zeros_like(h)                        # 消融：消息恒 0，深度不变
        elif messages is not None:
            c = messages
        else:
            b = self.bcast(h)                           # 同步轮次：都用上一轮隐状态
            total = b.sum(dim=1, keepdim=True)
            c = (total - b) / (self.n_agents - 1)       # 队友均值（去掉自己）
        h = h + cell(th.cat([h, c], dim=-1))            # 残差更新
    return self.head(h)                                 # (B, n, A)
```

这段代码解释了第六节对照的构造：`use_message=False` 时只把聚合消息 `c` 置零，`enc`、`bcast`、`cells`、`head` 模块全部保留，名义参数量因此与通信版相同（29443）；零消息分支不执行 `bcast` 投影，那部分权重不参与前向、也得不到梯度。`(total - b) / (n-1)` 的“去掉自己、取队友均值”对应同步轮次的更新要求。
