> RedMoon · 2026-11-12 · 课堂阅读笔记

同样是查找信息、调整参数或与他人协作，命令行、图形界面、语音、触摸和虚拟现实会给用户带来不同的操作成本。这节课从具体界面出发，讨论任务、用户能力、使用环境、成本和可靠性怎样影响设计选择。界面是否合适，要看用户能否理解当前状态、完成目标，并在出错时恢复。

课堂重点是命令行、图形界面、图标、多媒体、虚拟现实、网站、移动设备、家电和语音。课件第 56 页注明“本页往后不做考核”，因此笔、触摸、手势、触觉、多模态等内容集中放在第十节，作为课件拓展阅读。

## 一、选择界面之前，先明确任务与场景

课件提出的“哪种界面更好”，需要放进具体条件才能回答。例如，同样是寻找一个文件，熟悉命令的人可能更愿意输入一条命令；偶尔使用系统的人则需要文件夹、搜索框和可见菜单。在移动途中，持续看屏幕可能不方便；在安静会议室里，语音播报又可能干扰他人。

可以从以下几方面确定界面的要求：

| 需要明确的问题 | 对界面设计的影响 |
| --- | --- |
| 用户要完成什么 | 精确编辑需要可定位、可修改的表示；浏览信息可以采用较自由的探索方式 |
| 谁来使用、使用频率如何 | 专业用户可通过快捷方式提高效率；偶发用户需要较低的记忆负担 |
| 在哪里使用 | 噪声、光照、移动状态、双手是否被占用都会改变输入方式的可用性 |
| 出错后有什么影响 | 需要明确反馈、纠错和撤销；高后果操作应避免仅凭模糊输入直接执行 |
| 有哪些设备和资源约束 | 屏幕、续航、传感器、计算能力、成本与维护条件影响方案选择 |
| 是否涉及多人 | 要考虑共享参照、操作归属、同时输入和个人空间 |

“自然”也应按任务判断。说话是熟悉的表达方式，但用语音修改长文本中的一个标点未必方便；手势可以直观地控制旋转，却仍需要用户知道有哪些手势、系统何时开始识别。评价时应观察完成时间、错误率、学习成本与使用感受，不能只根据技术新旧下结论。

## 二、命令行：把常用操作压缩为明确指令

命令行通过键入命令、参数和对象来操作系统。例如，课件用 `ls` 展示列出文件的过程。用户知道命令含义时，可以用较少动作完成精确操作，也容易重复执行相同任务。

成本主要出现在学习和回忆阶段：用户需要知道命令叫什么、参数怎样组织、对象如何指定。已经熟练的功能不一定代表所有命令都能记住，低频操作仍可能需要查阅帮助。

因此，命令名、缩写和参数结构应保持一致。相似操作采用相似语法，错误反馈指出具体位置和修正方式，帮助信息应能从当前任务直接找到。快捷键也有类似特点：熟练后很快，但快捷键自身通常不提供完整的功能解释。

命令行适合高频、精确、可重复的操作。图形入口和命令入口也可以共同存在，让初学者先发现功能，再逐渐使用更快的操作方式。

## 三、图形界面：让对象与可执行操作看得见

### 1. WIMP 的四个组成部分

WIMP 指 Windows、Icons、Menus 和 Pointing device，即窗口、图标、菜单与指点设备。窗口划分工作空间，图标表示对象或功能，菜单列出候选操作，鼠标等设备把用户动作对应到屏幕位置。

窗口允许打开、关闭、移动、缩放、重叠和滚动，缓解了有限屏幕与大量信息之间的矛盾。窗口多了以后，新的问题是“怎样找到刚才那个窗口”。课件给出的辅助方法包括列表、标签页和缩略图。

标签页适合管理同一类任务，例如多个网页；缩略图提供内容线索，便于区分名称相似的窗口。标题只显示相同应用名时，用户仍要逐个打开确认，因此标签、标题和预览应尽量呈现能区分任务的内容。

### 2. 菜单形式与信息组织

| 菜单形式 | 常见用途 | 需要留意的地方 |
| --- | --- | --- |
| 平铺列表 | 直接呈现一组候选项 | 选项多时要分组、排序或提供搜索 |
| 下拉与级联菜单 | 节省常驻空间，按层级展开 | 深层菜单会增加定位和指针移动负担 |
| 弹出与上下文菜单 | 展示当前对象的相关操作 | 用户必须知道在哪里、怎样唤出菜单 |
| 折叠菜单 | 按需显示次要内容 | 折叠状态和展开入口要明显 |
| 大型展开菜单（mega menu） | 在二维区域中展示多个分组 | 分组名称和阅读顺序仍需清楚 |

菜单选择取决于选项规模、使用频率和设备。大型展开菜单可以减少深层级联，但不意味着所有小菜单都应改成大面板。手机上的展开菜单还必须满足触控与小屏阅读的要求。

课上以国家选择等例子说明：长列表只支持滚动时，用户要在大量项目中寻找目标；增加输入搜索、明确排序或合理分组，可以减少寻找成本。菜单文本也应说明动作，“置于顶层”通常比脱离上下文的“前面”更明确。

### 3. 简洁与可发现性

低频工具可以按需展开，让主要任务保留足够空间；常用操作则应留在容易找到的位置。把所有操作隐藏起来虽然能让界面看起来空，却会让用户增加搜索、试探和记忆。

窗口缩放时应重新安排内容：保留当前任务和必要控制，调整分组与排列，避免把原来的桌面界面整体缩小。布局变化还应尽量保持操作位置与命名的连续性，让用户能认出熟悉的功能。

## 四、图标：外形与功能之间怎样建立联系

### 1. 三种映射方式

课件把图标与其所指对象之间的联系分成三类：

| 映射方式 | 例子 | 理解依靠什么 |
| --- | --- | --- |
| 相似映射 | 文件图形表示文件 | 图形与对象的外观相似 |
| 类比映射 | 剪刀表示剪切 | 把现实动作的含义借到数字操作中 |
| 约定映射 | 用某个约定符号表示关闭等操作 | 用户对产品或文化习惯的学习 |

图标的含义必须结合上下文。一个 `×` 可能用于关闭窗口、取消操作或移除项目，不能脱离位置和提示就假定用户会理解成“删除”。抽象操作也很难靠一个物体形象完整表达，因此可以组合对象、方向箭头和状态标记。例如“本地文件上传云端”可由文件、云和朝向云的箭头共同表达。

### 2. 图标风格与辨识

课件展示了黑白、拟物、带阴影与扁平图标。课堂还讨论了透明、毛玻璃等视觉效果。风格可以服务于产品氛围，但辨识度首先取决于轮廓、对比、语义和上下文。

游戏里的图标可以承担情绪表达；专业工具则需要让功能和状态更容易区分。同一工具栏最好使用相近的线条粗细、大小和视觉复杂度，避免某个无关图标因为过度鲜艳而持续抢占注意力。

陌生功能可以配短文字。桌面端的悬停提示适合补充解释，但触摸设备没有稳定的悬停动作，关键含义应通过常驻标签、可访问名称或其他明确入口传达。

### 3. 课堂活动：旋转、裁剪与自动增强

课件第 24 页要求为相机编辑界面设计三个图标，再让其他人判断含义。可采用以下思路：

1. 旋转 90 度：用照片轮廓和转向箭头，辅以“旋转”标签，明确变化作用在照片上。
2. 裁剪：用裁剪框或角标表示保留的区域。应与缩放图标区分，避免让用户误以为只改变显示比例。
3. 自动增强：使用约定的魔棒或光效符号，同时给出“自动增强”文字，并允许预览、撤销。

检验时先让参与者说明自己认为图标会做什么，再观察实际操作。若必须先解释图标，才得到正确答案，就还没有证明它能够被独立理解。这是对课件活动的设计回答，不代表已实际完成用户测试。

## 五、多媒体：让不同表示共同支持理解

多媒体界面把文字、图形、音频、视频和动画组合起来，并通过超链接、点击和交互控制建立联系。用户可以从一幅图进入局部解释，播放对应动画，再回到原来的阅读位置。

课上的榫卯结构与产品展示例子说明：静态图适合呈现整体，旋转或拆解模型可以帮助观察连接关系，文字则负责说明名称与原理。不同媒介各自回答一个问题，用户才容易把它们联系起来。

设计时需要支持暂停、回看、定位和返回。让用户完成一次模拟操作、回答问题或记录结果，可以把浏览转化为主动加工；单纯同时播放动画、声音与文字，可能让人只关注最显眼的片段。

课件把浏览和长时间阅读作了区分。多媒体适合探索多种表示，长文阅读和精确编辑则需要稳定、安静的界面。专业软件也可以使用视频或模拟，只要它们服务于当前任务，并允许用户控制出现的时机。

## 六、虚拟现实：把交互放进可参与的空间

虚拟现实通过计算机生成的环境，让用户在三维空间中观察、移动和操作，形成身处其中的临场感。课件讨论了游戏、建筑设计、教学和模拟训练等用途，也提到用于恐惧情境训练的研究与应用例子。

设计问题集中在以下几个方面：

- 采用第一人称还是第三人称视角，是否方便理解自身位置与任务对象。
- 怎样移动和转向，头部、手部、控制器输入与画面变化是否一致。
- 如何选择对象、操作工具和阅读信息，是否需要频繁切换输入方式。
- 佩戴重量、显示延迟、视觉运动与身体运动的不一致，会不会影响舒适度。
- 用户进入虚拟环境后，怎样继续感知现实中的边界、障碍和他人。

触觉反馈可以配合视觉，通过振动或机械阻力等方式表现接触感。这里应按具体硬件的反馈机制理解“碰到墙”的体验，不能把课堂中的直观类比理解为普通手套能够直接阻断人的神经信号。

课堂特别提醒，沉浸会减少用户对现实环境的注意。边界提示、环境感知、明确退出和暂停方式应共同支持安全使用，不能只依赖危险发生时的一个弹窗。重量、续航、供电和计算负载也需要放进实际使用条件中评估。

## 七、网站：让用户知道位置、内容与去向

### 1. 三个基本问题

课件引用 Veen 的三个问题：

1. 我在哪里？
2. 我可以去哪里？
3. 这里有什么？

标题、当前导航状态和面包屑回答“在哪里”；清晰的链接和菜单回答“可以去哪里”；内容分组、摘要和主要操作回答“这里有什么”。

面包屑通常表示页面在信息层级中的位置，例如“首页 → 学生服务 → 场地预约”。用户可以直接回到某一级，而不必反复按浏览器返回。它不一定记录每一步访问历史，层级路径与实际浏览轨迹应分清。

### 2. 响应式布局

响应式设计根据可用空间调整布局和内容呈现，例如把多列改为单列、重新安排导航、让图片缩放、使文字换行。关键是保留可读字号与可操作目标，不能把桌面页面等比例压成很小的一张图。

重新布局也不必然增加分页。是否分页、怎样加载内容、是否保留筛选条件，都是另外的设计决定。用户从桌面切到手机后，仍应能认出同一个任务，并找到主要入口。

### 3. 无限滚动与广告

无限滚动减少连续浏览时的分页操作，适合持续发现新内容。代价是位置不容易记住，返回某一条内容、比较多个结果或找到页尾可能更困难。面向明确目标的查询，应考虑搜索、筛选、稳定链接、位置恢复等支持。

广告和推荐也会占用注意力。闪烁、持续覆盖正文、难以关闭的浮层，会干扰用户原本的任务。设计不能只看用户停留多久，还要看任务是否完成、内容是否能找到以及关闭干扰是否容易。

### 4. 课堂网站讨论怎样分析

课件第 42 页要求观察学校网站。可按“查找通知”“进入教务系统”“寻找办事入口”等具体任务逐一检查：当前站点名称是否清楚，跳转到子系统后有没有当前位置提示，返回主站的路径是否可见。

跨多个子系统时，即便每个页面单独可用，也可能因标题、导航和登录反馈不一致而使用户迷失。分析时应记录实际入口与跳转结果，再提出改进；仅凭记忆不能断言当前官网具体哪里有缺陷。

## 八、移动与家电：操作条件决定控制方式

### 1. 移动设备

手机随人移动，屏幕较小，用户可能单手操作，也可能处于走动、光照变化或注意力分散的环境。应优先展示当前任务需要的信息，避免把大量低频设置挤进首屏。

手指会遮挡目标，触控精度和鼠标不同。命中区域应足够大，相邻目标要有间距，关键操作还要有明确反馈。课件第 46 页给出了 44 × 44 points 的示例；它用于说明触控目标需要合适尺寸，不能直接当成所有平台的物理像素统一标准。

课件用倾斜手机的模拟饮料、二维码等例子说明设备能力如何进入交互。倾斜和运动可由运动传感器提供信息，摄像头可以把二维码作为现实物体到数字页面的入口。使用传感器时，应让用户理解系统识别到了什么，并为识别失败准备可继续操作的入口。

### 2. 家电与短时界面

洗衣机、烤面包机、遥控器和售票设备常用于一次较短的操作，用户通常希望迅速开始任务。控制项应围绕常用目标安排，形状、标记和反馈帮助用户判断怎样使用。

实体旋钮与按钮可以提供触感和固定位置；屏幕控件更便于改变选项与展示状态。两者的选择要结合操作频率、清洁条件、使用环境以及是否需要边看别处边操作。

按钮少不等于不会误用。课上的烤面包机例子说明，用户对开口、放置方向和启动方式仍可能有不同理解。设计需要清楚呈现开始、运行、结束与停止状态，并合理分配用户控制和自动控制；必要的安全约束应由产品本身承担。

## 九、语音：识别之外，还要设计对话

语音适合短指令、简要查询和双手被占用时的操作，也可以为视觉受限用户提供另一种输入输出通道。长选项列表和精确编辑则会暴露它的顺序性：用户通常要等待系统逐项说完，难以像看菜单那样同时比较。

### 1. 支持用户打断

课件用 barge-in 表示用户在系统尚未说完时就作出回应。电话菜单播报到所需选项后，用户应能够立即选择；语音助手开始冗长回答时，也应能被“停止”或新指令打断。

打断后，系统需要停止旧输出、识别新意图，并让用户知道当前处理的是哪件事。否则即使每句话识别正确，对话仍可能错位。

### 2. 分步补全与针对性确认

系统主导的对话逐项询问信息，容易控制流程，但步骤较多；用户主导的表达允许一次给出多个条件，系统随后补问缺失部分。

例如用户说“帮我设个闹钟”，系统只需询问时间；用户说“明天上午九点提醒我交作业”，系统已经获得日期、时间与事项，不必重新从头问一遍。若只听不清“九点还是十点”，就针对这个字段确认，并保留其余已确认内容。

对话修复应说明系统理解到了什么，以及还差什么。用户换一种说法重试后，仍反复播放相同长提示，会把识别错误变成持续的交互负担。

### 3. 环境、隐私与不同用户

噪声、语速、口音、表达习惯和多人交谈都会影响交互。系统需要清楚提示是否正在收音、何时处理完成，并提供触控或文字入口，让用户在不方便说话时继续任务。

家庭共享设备还涉及谁在发出指令、信息会被谁听到。面向儿童的产品，应采用容易理解的确认方式；播报声音可以按偏好选择，但声音风格不能替代识别、反馈与错误恢复的设计。

## 十、课件拓展：笔、触觉、多模态与空间界面

以下内容对应课件第 56—110 页。它们把输入输出扩展到身体、实体物品和周围空间，各类界面的设计问题仍围绕可理解性、控制与反馈展开。

| 界面类型 | 交互方式与课件例子 | 主要设计问题 |
| --- | --- | --- |
| 笔输入 | 用触控笔写字、画图、批注；智能笔记录纸上笔迹 | 笔迹与数字结果是否对应，怎样选取、修改和共享 |
| 触摸与多点触控 | 点击、拖动、滑动、捏合缩放；交互桌面 | 目标大小、手指遮挡、手势学习、屏幕方向和多人可达范围 |
| 非接触手势 | 摄像头或传感器识别手臂、手部动作；课件展示手术环境与车载示例 | 怎样识别动作起止，区分命令和无意动作，提供确认与取消 |
| 触觉界面 | 振动、力反馈，以及课件介绍的超声触觉等方式 | 刺激位置、强度、节奏与含义是否可区分，是否舒适 |
| 多模态界面 | 结合语音、视觉、触摸、视线等输入输出 | 多通道是否互补，时序怎样对齐，冲突时如何解释 |
| 共享界面 | 大屏、交互白板、多人触控桌 | 公共参照、轮流与同时操作、个人区域及操作归属 |
| 实体交互 | 移动物理模型、积木或方块，引起数字变化；如 Urp、Flow Blocks | 实体动作与数字结果的映射是否明确，是否便于共同探索 |
| 增强现实（AR） | 把数字信息叠加到现实对象或视野中；导航、试戴等 | 叠加位置是否准确，是否遮挡现实任务，偏移时如何处理 |
| 可穿戴界面 | 手表、眼镜、织物等把信息交互带到身体上 | 重量、佩戴与清洗、更换部件、控制入口和旁观者隐私 |
| 机器人与无人机 | 远程操控、家务辅助、协作与陪伴 | 行为意图、控制权、物理行动的后果，以及图像采集的边界 |
| 脑机接口 | 从神经活动中提取信号以选择屏幕目标或控制设备 | 训练与校准、误判、反馈、目标布局，以及敏感信息的保护 |
| 智能与情境感知界面 | 根据环境信息调节设备或空间 | 自动动作是否符合目标，用户怎样查看原因、修正与接管 |
| 形变与数据物理化 | 可升降杆阵列、实体方块等用形状或材料表现数据 | 物理变化怎样编码信息，尺度与分辨率是否足够，用户能否理解 |
| 全息类呈现 | 用投影或显示技术营造人物处于空间中的视觉效果 | 尺寸、视角、社交距离，以及双方如何交流；需区分具体显示机制 |

多模态与多媒体的侧重点不同：多媒体关心文字、视频等内容表示的组合，多模态关心人通过哪些感知与动作通道交换信息。一个播放视频的网站已经有多种媒体，却不一定能联合理解语音和手势。

共享界面与远程协同也有区别。多人围着同一张交互桌，可以直接指向同一对象、观察他人动作；各自使用电脑时，则需要光标、选区、权限或操作反馈来建立共同参照。更大的屏幕不自动带来更好的合作，任务分工、参与机会和个人空间同样重要。

## 十一、把设计原则放进一个完整任务

以“预约一间教室”为整理练习，可以把本课内容串成一次具体交互：

1. 页面先显示日期、人数、地点与空闲时段，用户能判断当前查询条件和结果。
2. 桌面端允许并排比较教室，手机端改为可筛选列表，保留足够大的点击区域。
3. 面包屑和页面标题标明“学生服务 → 场地预约”，进入确认页后仍有返回入口。
4. 图标辅助表示容量、位置和设备，陌生含义配文字，已选时段同时用文字与状态样式呈现。
5. 语音可用来输入“下周三下午、二十个人”，系统补问缺失条件，并在最终确认前展示识别结果。
6. 无空闲时段时说明冲突条件，保留已填信息，允许修改时间或地点。

检验这套设计时，观察用户能否独立找到入口、完成预约、发现错误并修改；再记录完成时间、误选和求助位置。界面的价值最终体现在这些具体动作上。
